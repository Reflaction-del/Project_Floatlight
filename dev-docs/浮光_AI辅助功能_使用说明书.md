# 浮光世界观编辑器 · AI 辅助功能使用说明书

> 适用版本：**v2.0.0**（含 5 项 AI 辅助功能）
> 模块位置：实体库、视觉物料生成器、AI 侧栏、工具栏

浮光世界观编辑器的 AI 辅助功能，核心目标是**把你的世界观数据更快地产出、更聪明地补全**。所有 AI 产出都不会直接落库，而是先进入「提案中心」由你逐条确认，避免模型出错污染你的世界观。

---

## 一、前置准备：配置 AI 模型

所有 AI 功能都依赖一个 **OpenAI 兼容协议**的模型接口（本地如 LM Studio / Ollama，或云端如 OpenAI、DeepSeek、通义等均可）。

1. 打开左侧 **AI 侧栏（Copilot）**。
2. 在模型设置中填写：
   - **Base URL**：接口地址（如 `http://localhost:1234/v1` 或厂商地址）。
   - **API Key**：接口密钥（本地模型可填任意占位符）。
   - **模型名（Model）**：具体模型标识。
3. 建议为不同功能准备不同模型：
   - **文本类**（文章抽取、实体关联、NL 建模板）：任意支持 JSON 输出的对话模型即可。
   - **视觉类**（多模态设卡）：需「chat 格式 + 支持 `image_url` 多模态输入」的视觉模型（如 `gpt-4o`、`qwen-vl` 等）。若用非 chat 格式，多模态设卡会报错提示你改用 chat 格式。

> 连接状态可在 AI 侧栏「测试连接」中验证。

---

## 二、核心机制：统一提案队列（功能4 · 基座）

这是 5 个 AI 功能的共同底座。**AI 不会直接修改你的世界数据**，而是把每一次生成结果包装成一个「提案」，由你确认后才写入。

### 2.1 提案中心

- 入口：顶部工具栏 **🗳️ 提案中心** 按钮，右上角角标显示当前**待处理数量**。
- 打开后按「来源」分组展示（如「文章抽取」「实体关联」「多模态设卡」「模板生成」「对话」等）。
- 每条提案可：
  - **采纳**：真正写入世界数据（新增实体 / 新增关系 / 更新字段 / 新增模板）。
  - **拒绝**：丢弃该条。
  - **全部采纳**：一键采纳当前分组全部待处理项。
  - **清空已处理**：移除已采纳/已拒绝的提案，保持列表清爽。
- 顶部显示「待处理 / 已处理」计数。

> 设计意图：模型可能抽错实体名、认错关系，提案机制让你在落库前把关，世界观数据始终由你掌控。

### 2.2 对话持久化

- AI 侧栏的对话历史会**自动按当前世界落盘**（存入 `WorldData.chats`）。
- 切换世界时，旧世界对话自动保存、新世界对话自动载入；关闭/重开应用后对话仍在。
- 无需手动导出，天然跟随世界文件。

## 三、功能1：导入文章抽取实体与关系

**入口**：实体库顶部工具栏 → **📥 导入文章并抽取**

适用场景：你有一段设定文、剧情稿、百科词条，想快速把它拆成结构化实体与关系。

操作步骤：

1. 点击按钮打开弹窗，可选择：
   - **上传文件**：`.txt` / `.md`。
   - **直接粘贴**：把文本粘进文本框。
2. 点击 **🤖 开始抽取**，AI 会识别文中的：
   - **实体**：自动归类到 角色 / 势力 / 地点 / 事件 / 规则 五种类型之一，并给出名称、简介。
   - **关系**：实体之间的关联（隶属 / 敌对 / 发生于 / 因果 / 亲属 / 自定义）。
3. 预览抽取结果：
   - 已存在的同名实体（不区分大小写）会被**自动去重跳过**，不会重复建卡。
   - 关系若无法解析到具体实体，会被跳过（不会生成悬空关系）。
4. 确认后点击 **加入提案队列**，自动跳转到「🗳️ 提案中心」。
5. 在提案中心逐条**采纳**，实体与关系即写入实体库。

> 提示：抽取质量取决于模型能力。复杂文本建议先人工整理段落，或分段抽取。

## 四、功能3：实体名称关联 / 消歧

**入口**：实体库顶部工具栏 → **🔗 实体关联**

适用场景：你有一段提到很多名字的文本（如人物对话、事件描述），想把这些「名字」对应回实体库里已有的实体，或发现新实体——用于**导入去重**和**独立整理**两种需求。

提供三种匹配模式：

| 模式 | 说明 | 何时用 |
|---|---|---|
| **精确匹配（exact）** | 文本中的词与实体名/别名完全一致才关联 | 名字规范、无错别字 |
| **模糊匹配（fuzzy）** | 基于编辑距离 + 中文滑窗 + 包含关系，容忍错别字 / 简称 | 文本有错字、用了昵称 |
| **大模型（llm）** | 由模型理解语义，判断「这段话提到的 X」指向哪个实体，或应新建 | 上下文复杂、需要语义消歧 |

操作步骤：

1. 选择一种模式，把文本粘贴进框（模糊/精确模式无需联网，大模型模式需调用模型）。
2. 点击 **🔗 开始关联**，AI 或算法会产出关联结果：
   - **alias（别名）**：把文本中的叫法登记为某实体的别名（写入实体 `tags`）。
   - **new（新建）**：判断这是一个实体库里没有的新实体，建议新建并给出类型。
3. 预览结果，点击 **加入提案队列** → 提案中心逐条采纳。

> 该工具既可在「导入文章后做去重」，也可作为日常整理实体别名的独立工具使用。

## 五、功能2：多模态设卡（图片 → 实体卡）

**入口**：实体库顶部工具栏 → **🖼️ 多模态设卡**

适用场景：你有一张角色立绘、一张地图、一个徽章图，想让 AI 看图自动生成一张带图、带属性的实体卡。

前置：需要配置**支持多模态（image_url）的视觉模型**，且为 chat 格式（见第一节）。

操作步骤：

1. 在弹窗中**上传 / 拖拽 / 粘贴（Ctrl+V）**一张图片。
2. （可选）填写一段**文字提示**（如「这是主角，冷峻的剑客」）和**类别预设**（角色/势力/地点/事件/规则）。
3. 点击 **🤖 AI 设卡**，模型会返回结构化卡片：
   - 名称、类别、图标、简介、格言、编号、图注。
   - 自动识别并填充**物料属性字段**（如编号 `id`、格言 `signature`）。
4. 结果可**直接编辑**修正（名称/类别/图标/简介/字段均可改）。
5. 右侧**实时预览**复用「身份卡（idCard）」模板，渲染出**文字 + 图片**的实体卡效果（与导出一致）。
6. 点击 **🗳️ 加入提案队列** → 提案中心采纳后，实体（含图片与字段）写入实体库。

> 生成过程中可随时点「停止」中断。图片通过 `portrait` 上传模式带入卡片，导出 PNG/PDF 时同样显示。

## 六、功能5：自然语言生成物料模板

**入口**：视觉物料生成器顶部工具栏 → **🪄 NL 建模板**

适用场景：你想做一张「人物档案卡 / 势力对比图 / 时间线徽章」等物料，但不想手动拖块，直接用一句话描述即可。

操作步骤：

1. 点击按钮，输入一句自然语言描述，例如：
   > “做一张角色介绍卡：左边放头像，右边是姓名、称号、种族、简介，底部一条光谱条按势力上色。”
2. （可选）选择**类别预设**（角色/势力/地点/事件/规则）帮助模型定位。
3. 点击 **🤖 生成模板**，模型输出一张结构化 **MaterialTemplate**（包含文本、图片、字段绑定、分隔线、光谱条、图表等区块）。
4. 右侧**实时预览**用占位实体把 `{entity:name}` 等字段绑定渲染出来，方便你确认版式。
5. 可修改**模板名称 / 类别**。
6. 点击 **🗳️ 加入提案队列** → 提案中心采纳后，模板加入你的物料模板库，可在物料生成器中直接使用。

> 字段绑定语法沿用既有规则：`{entity:name}`（实体名）、`{customField:key}`（自定义字段）、`{world:xxx}`（世界属性）。

## 七、实体类型与关系类型速查

AI 抽取/关联时只会产出以下固定枚举，便于你核对结果：

**实体类型（5 种）**
- `character` 角色 / `faction` 势力 / `location` 地点 / `event` 事件 / `rule` 规则

**关系类型（6 种）**
- `belongs` 隶属 / `enemy` 敌对 / `occurs` 发生于 / `causal` 因果 / `kin` 亲属 / `custom` 自定义

## 八、常见问题与注意事项

- **AI 结果没进实体库？** 所有 AI 产出都在「🗳️ 提案中心」等你采纳，采纳后才落库。这是设计使然，不是 bug。
- **多模态设卡报错？** 多半是模型不支持 `image_url` 或不是 chat 格式，请换用视觉模型（见第一节）。
- **抽取到的关系丢失？** 关系必须能解析到两个已存在（或本次同批新建）的实体；解析不到的会被跳过。
- **对话记录在哪？** 自动跟随当前世界文件，切换世界/重开应用都不丢。
- **模型返回非 JSON 导致解析失败？** 文本类功能对模型 JSON 输出能力有一定要求；若频繁失败，换用更强或开启 JSON mode 的模型。
- **提案来源标签含义**：文章抽取 / 实体关联 / 多模态设卡 / 模板生成 / 物料字段 / 对话 / 手动——对应各自功能的产出。
