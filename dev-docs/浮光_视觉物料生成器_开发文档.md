## 2. 模块概述

### 2.1 目标（In Scope）
- 用户定义/选择**美术风格**与**物料模板**，绑定实体数据，稳定产出风格统一的视觉图片。
- 支持批量、套系、变量矩阵产出。
- 跨物料保持头像/编号/风格令牌一致（复用 Consistency）。

### 2.2 非目标（Out of Scope，v1）
- 不替代实体库本身的数据录入（仅消费实体数据）。
- v1 不内置图像编辑/PS 类功能（仅"生成 + 微调 + 重生成局部"）。
- AI 图像为可选增强，离线也能产出基础物料。

### 2.3 与现有架构关系
复用现有五大模块，新增四大子系统：

| 现有模块 | 复用方式 |
|---|---|
| 实体库 `src/features/entities` | 作为物料的数据源（角色/组织字段） |
| 世界上下文 `src/utils/worldContext.ts` | 绑定当前世界观 + 风格 |
| 一致性检查 `src/utils/consistency.ts` | 扩展视觉一致性校验 |
| AI 侧栏 `src/components/CopilotSidebar.tsx` + `src/utils/ai.ts` | 文案/头像/Logo 生成 |
| 分享 `src/features/share/SharePanel.tsx` | 导出包/画廊/分享 |

新增：`Style System` / `Template Engine` / `Render Pipeline` / `Export`。

## 3. 技术选型

### 3.1 渲染方案对比

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. Electron 离屏窗口捕获**（`webContents.capturePage` / `printToPDF`） | 印刷级保真、多倍率可控、字体/PDF 最稳 | 需主进程配合、异步 | **主路径（高质量/打印）** |
| **B. 渲染进程 DOM 截图**（`html-to-image`/`dom-to-image`） | 实现快、无需主进程 | 字体/跨域/伪元素易丢、超大图崩 | **快速路径（预览/社交图）** |
| C. 服务端渲染 | 跨平台一致 | 需后端、隐私/成本 | 暂不考虑 |

**推荐**：预览用 React 实时渲染（所见即所得）；导出时优先 A（离屏窗口），B 作为轻量兜底。同一套模板 JSON 同时驱动 React 预览与离屏 HTML，保证一致。

### 3.2 新增依赖（建议）
- `html-to-image`（快速截图兜底）
- `zod`（模板/风格 JSON 运行时校验）
- `uuid`（资产/物料实例 ID）
- 模板渲染无需额外引擎，用 React 递归组件解释模板 JSON。

### 3.3 状态管理
新增 `src/store/materialStore.ts`（Zustand）：
- `styles: StyleToken[]`、`activeStyleId`
- `templates: Template[]`、`activeTemplateId`
- `assets: AssetMeta[]`
- `renderQueue: RenderJob[]`
- `preview: { entityId, templateId, styleId, overrides }`

### 3.4 存储
- 风格包：`.fuguestyle`（JSON + 资源引用）
- 模板：`.fugutemplate`（JSON）
- 资产：归入世界观工程目录 `assets/materials/`（头像/Logo/纹理）
- 物料实例配置随世界观存档（`manifest.json` 记录来源，便于回溯）

## 4. 数据模型与类型定义

### 4.1 风格令牌 `StyleToken`
```ts
interface StyleToken {
  id: string;
  name: string;
  worldviewId: string;            // 绑定世界观
  colors: {
    primary: string; secondary: string; bg: string;
    danger: string; accent: string; forcedMono?: boolean; // 强制黑白
  };
  fonts: {
    title: string; body: string; handwriting: string; mono: string;
    // 引用本地/导入字体名
  };
  texture: {
    type: 'plain' | 'scanned' | 'paper' | 'screen' | 'parchment';
    noise: number;          // 0-1 噪点强度
    aging: number;          // 0-1 做旧程度
  };
  iconSet: IconRef[];        // 该世界观图标（骷髅/地球裂解…）
  logo?: AssetRef;           // 机构主标识（矢量，可反色）
  signatureStyle: 'handwriting' | 'stamp' | 'auto';
  layout: {
    margin: number; columns: number;
    headerFormat: string; footerFormat: string; // 支持 {{worldview.code}}
    tableStyle: 'three-line' | 'boxed' | 'none';
  };
  motifs: MotifRef[];        // 角标/分隔线/水印
  toneLexicon: Record<string, string>; // 黑话词典，供 AI 写文案
}
```

### 4.2 模板 `Template`
```ts
interface Template {
  id: string;
  name: string;
  kind: 'staff-file' | 'id-card' | 'menu' | 'recruitment'
      | 'blueprint' | 'report' | 'notice' | 'timeline-card'
      | 'character-sheet' | 'faction-sheet' | 'custom';
  applicableStyles: string[];  // ['*'] 表示通用
  width: number; height: number; // 画布尺寸(px@1x)
  root: Block;                  // 组件树
  fields: FieldBinding[];       // 需要的实体字段声明
}

type Block =
  | { type: 'text'; slot?: string; content?: string; style: TextStyle; cond?: Cond }
  | { type: 'image'; slot?: string; fit: 'cover'|'contain'; frame?: string; cond?: Cond }
  | { type: 'table'; rows: Row[]; cond?: Cond }
  | { type: 'divider'; variant: string }
  | { type: 'icon'; ref: string; size: number }
  | { type: 'repeat'; of: string; item: Block[] }   // 循环（如技能列表）
  | { type: 'group'; children: Block[]; layout: 'row'|'col' };

interface FieldBinding {
  key: string;                  // 模板内变量名，如 name
  source: 'entity' | 'style' | 'literal' | 'ai';
  path?: string;                // entity.spectrum_color
  fallback?: string | ((e: Entity)=>string);
  formatter?: 'upper' | 'abbr' | 'random_id' | 'none';
}
```

### 4.3 资产 `AssetMeta`
```ts
interface AssetMeta {
  id: string;
  kind: 'portrait' | 'logo' | 'texture' | 'icon' | 'signature' | 'background';
  ownerEntityId?: string;       // 角色头像/签名绑角色
  file: string;                 // assets/materials/xxx.png
  refImageId?: string;          // AI 生成时的参考图锁，保证同角色一致
  usedBy: string[];             // 被哪些物料引用（一致性/删除告警）
}
```

### 4.4 实体扩展字段
在现有实体类型上扩展可视化字段（不改存量数据，缺省即走兜底）：
`portrait`、`spectrumColor`、`signature`、`badge`、`healthStatus`、`cv`、`workSummary`、`cyborg`、`affiliation`。

## 5. 架构设计

### 5.1 目录结构
```
src/features/materials/
  MaterialForgeView.tsx      # 主界面（左:数据/模板, 中:预览, 右:风格/导出）
  StyleSystem/
    StyleList.tsx
    StyleEditor.tsx          # 编辑令牌（取色器/字体/纹理）
    styleInfer.ts            # 参考图反推令牌 (AI)
  TemplateEngine/
    TemplateList.tsx
    TemplateEditor.tsx       # 可视化拖拽 / JSON 编辑
    TemplateRenderer.tsx     # 递归解释 Block -> React
    bindings.ts              # 字段->槽位解析
  Render/
    previewToHtml.ts         # 模板+数据+风格 -> 独立 HTML 字符串
    exportImage.ts           # 调主进程 capturePage / html-to-image
    exportPdf.ts             # printToPDF
  Batch/
    BatchPanel.tsx
    queue.ts                 # 渲染队列
  Consistency/
    visualConsistency.ts     # 视觉令牌&角色跨图一致校验
  store.ts                   # materialStore
  types.ts
electron-main.cjs            # 新增: ipc 'material:capture' / 'material:pdf'
```

### 5.2 数据流
```
Entity + Style + Template
   → bindings.resolve() 填充槽位 (含 ai 兜底)
   → TemplateRenderer / previewToHtml 生成 HTML(CSS 变量来自 StyleToken)
   → 预览: React 渲染 | 导出: 离屏窗口 capturePage / printToPDF
   → 产物 PNG/PDF/SVG + manifest.json
```

## 6. 核心子系统详细设计

### 6.1 Style System
- `StyleEditor`：色板取色器、字体下拉（接入 `font-list` + 导入）、纹理/噪点/做旧滑块、图标上传、Logo 上传、语气词典键值表。
- `styleInfer.ts`：上传参考图 → 调 AI 提取配色/字体气质/纹理 → 生成 `StyleToken` 草稿，用户微调后保存。
- 风格与世界观绑定：切换世界观自动带出主风格 + 子风格。

### 6.2 Template Engine
- `TemplateRenderer`：递归渲染 `Block` 树；`cond` 用简单表达式求值（如 `entity.cyborg === true`）。
- `bindings.resolve(entity, style, template)`：把 `FieldBinding` 解析成最终字符串/资源；`source:'ai'` 时异步调 AI 并标记"待审核"。
- `TemplateEditor`：可视化拖组件 + 绑定字段；高级模式直接编辑 JSON；实时预览。

### 6.3 Render Pipeline
- `previewToHtml(resolved)`：输出自包含 HTML（内联 CSS 变量 + 字体 @font-face + 纹理 dataURI），供离屏窗口加载。
- 导出主路径：主进程 `ipc 'material:capture' { html, scale, clip }` → `webContents.capturePage` → 返回 PNG Buffer。
- 快速路径：渲染进程对预览节点 `html-to-image` 直接出图（社交图场景）。
- 字体保证：导出前确认字体已加载（`document.fonts.ready`），避免回退。

### 6.4 Export
- PNG：1x/2x/4x（deviceScaleFactor），按平台预设尺寸或自定义。
- PDF：`printToPDF`（A4/自定义，印刷用）。
- SVG：模板含矢量元素时可导出（Logo/图标），位图部分转 base64。
- 批量：整包 zip + `manifest.json`（记录每张图 entity/template/style 来源）。

### 6.5 Consistency（视觉维度扩展）
- `visualConsistency`：扫描同世界观已生成物料，校验主色/字体/Logo/页眉格式是否漂移；角色头像/编号/光谱色跨图是否一致。
- 角色改名/换头像时提供"全局更新引用"。
- 风格冲突：给"奇幻羊皮卷"风套"赛博霓虹"模板 → 提示 + 一键适配建议。

### 6.6 Batch
- `BatchPanel`：勾选多个实体 → 套同一模板+风格 → 进 `queue` 顺序渲染。
- 套系生成：预置"完整物料包"配方（档案×全员 + ID 卡×全员 + 菜单 + 海报 + 蓝图）。
- 变量矩阵：同一实体 × 多状态版本 → 矩阵出图。
- 队列可暂停/重试失败项；并发上限保护 UI 不卡。

### 6.7 AI 辅助（抽象层，provider-agnostic）
- 文案：用 `toneLexicon` 构造 prompt，生成档案/菜单/公告，避免出戏。
- 头像：参考图 + `StyleToken` + 角色特征 → 生成；`refImageId` 锁定保证同角色多姿势一致。
- Logo/图标：从令牌生成阵营徽记。
- 自动补全：字段空缺 AI 补全并标"待审核"。

## 7. 关键流程

### 7.1 单物料生成（时序）
1. 用户选实体 → 选模板 → 选风格。
2. `bindings.resolve` 填充槽位；AI 字段异步补全（标待审核）。
3. `previewToHtml` → React 预览渲染（实时）。
4. 用户微调（换头像/改文案/调风格）。
5. 导出：主进程 `capturePage`（PNG）或 `printToPDF`。
6. 写 `manifest.json`，资产引用计数 +1。

### 7.2 批量生成
- 选 N 实体 + 1 模板 + 1 风格 → 入队 → 逐张 resolve+render+export → zip + manifest。

### 7.3 风格反推
- 上传参考图 → `styleInfer` 调 AI → 生成 `StyleToken` 草稿 → 用户在 `StyleEditor` 微调 → 保存为世界观风格。

## 11. 验收标准

| 维度 | 标准 |
|---|---|
| 功能 | 选 1 实体 + 1 模板 + 1 风格 → 30s 内产出 PNG，版式正确、字段填充无误 |
| 一致性 | 同角色在 2+ 物料中头像/编号/光谱色完全一致；改风格后同世界观物料同步 |
| 批量 | 10 实体批量产出成功率 ≥ 95%，失败可重试 |
| 保真 | 导出 PNG 与预览在字体/配色/版式上无肉眼差异 |
| 性能 | 批量 10 张不阻塞主 UI（队列异步） |
| 兼容 | 离线（无 AI）仍可产出基础物料 |

## 12. 风险与权衡

| 风险 | 缓解 |
|---|---|
| AI 头像不可控/出戏 | HTML 版式为主，AI 仅增强；参考图锁定 + 人工审核 |
| 字体跨平台缺失 | `font-list` 探测 + 用户导入 + 风格令牌回退链 |
| 渲染保真度（DOM 截图丢细节） | 主路径用 Electron 离屏窗口捕获，非 DOM 截图 |
| AI 成本/隐私 | 默认本地排版零成本；AI 为显式开关，可选 provider |
| 模板 JSON 复杂度 | `zod` 校验 + 可视化编辑器，降低手写门槛 |
